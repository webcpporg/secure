= secure: side-channel and secret-in-memory primitives for {cpp}
:toc: left
:toclevels: 2
:idprefix:
:sectanchors:
:example-caption!:
:attribute-missing: warn

secure holds the side-channel and secret-in-memory primitives that the
libraries of https://github.com/webcpporg/webcpp[webcpp] share, for a
{cpp}20 program on every target webcpp has. It is not a cryptographic library:
it holds no algorithm, only what an algorithm's implementation needs so that
its timing and its secrets in memory do not leak, and what a program needs
around an algorithm to do the same.

The page teaches one primitive in each chapter, opening with what it guards
against, showing a program of `example/` that the build compiles and runs on
every target with the output it prints, and ending with what the primitive does
not do: <<secure-guard>> (the DIT guard), <<secure-erase-secret>>,
<<secure-secret>>, <<secure-constant-time-equal>>, <<secure-declassify>> and
<<secure-blocks>> (masks, selection and table lookup). <<secure-performance>>
is what the guard costs, measured. The <<reference,reference>> that closes the
page lists every name the headers declare.

== Reference

Every name secure declares, in the namespace `webcpp::secure`, from the Doc
Comments of its headers: each class, function, type and enumerator with its
declaration, what it does, what it asks of its caller and how it fails. The
other sections teach the library; this one is where a name is looked up.
