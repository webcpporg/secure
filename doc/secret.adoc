[#secure-secret]
== Secrets that wipe themselves: `secret<N>`

A shared secret, a session key or a converted secret key is `N` bytes that
should live in one object and leave memory with it. `secret<N>`, in
`<webcpp/secure/secret.hpp>`, holds its bytes in an array of its own and wipes
them, with the volatile stores and the fence of `erase_secret`, when it is
destroyed and when it is moved from. Every secret that crypto gives back is a
`secret<N>`.

It is not copyable: a copy is asked for by name, `clone()`, and the caller owns
it. A move takes the bytes and wipes the source, and a move to itself changes
nothing. `bytes()` gives a `std::span<std::uint8_t const, N>` to read, which a
cipher's key schedule or an HKDF takes as its input without a copy, and a
`secret<N>` converts to that span where a function takes it. `writable()` gives
the span for the code that fills it, as a library does. Neither view is offered
on a temporary `secret<N>`, whose bytes would be wiped before the span is read:
the program keeps the secret in a variable first. A secret of no bytes does not
compile, and `constant_time_equal` takes a `secret<N>` directly
(<<secure-constant-time-equal>>).

*What it is not.*

* It wipes its own storage, and only that. A copy of `bytes()` into a string,
  a vector or a log is the program's, to erase with `erase_secret`, and a move
  or a `clone` may leave copies in registers or temporaries that no library
  reaches.
* It does not lock the memory, as `erase_secret` does not: the page may be
  swapped to disk while the secret is in it.
